SIH Problem Statement Explorer is a browsable database for the [Smart India Hackathon 2026](https://sih.gov.in) problem statement set. Instead of scrolling through a static PDF, every problem statement is searchable, filterable, and sortable, and comes with an AI-assisted breakdown covering innovation scope, invention effort, competitive landscape, a 36-hour build plan, and an evaluator-style scorecard — everything a team needs to pick a problem statement and start building faster.

> [!NOTE]
> The scoring and analysis shown for each problem statement is generated by a rule-based, AI-assisted process, not by an official SIH evaluator. Treat it as a research aid, not a guarantee of how a jury will score your idea.

## Features

- **Search & filter** — full-text search across title, organization, theme, and description, with single-select filters for category, theme, organization, innovation scope, invention effort, and verdict.
- **Smart sorting** — sort by deadline, competitiveness (submissions so far), effort, innovation scope, or overall verdict.
- **Per-PS deep dive** — each problem statement opens into five tabs:
  | Tab | Content |
  | --- | --- |
  | Overview | Plain-language summary, why it matters, pain points |
  | Analysis | Innovation scope, invention effort, and competitive landscape notes |
  | Evaluator Lens | A scorecard on innovation, invention, technical feasibility, and impact |
  | 36-Hr Plan | A phased build plan (idea → prototype → integration → polish) with a "how to stand out" note and SWOT |
  | Unlock More | Team fit, AI-buildability split, data/resource availability, and likely judge questions |
- **Stats at a glance** — live counts of problem statements, themes, organizations, and the software/hardware split.
- **Fast by design** — the list view loads a lightweight index (`ps_list.json`); the heavier per-PS analysis is fetched on demand only when you open a problem statement, and detail pages are route-split so they aren't part of the initial bundle.
- **Data provenance marks** — problem statements with a corrected theme/category are flagged, and open-ended AICTE "open theme" statements are labeled as ideation categories rather than fully-specified briefs.

## Tech stack

- [React 18](https://react.dev) with [React Router](https://reactrouter.com) for routing
- [Vite](https://vitejs.dev) for tooling and bundling
- [Tailwind CSS](https://tailwindcss.com) for styling, with a custom blueprint/drafting-plate theme
- [Framer Motion](https://www.framer.com/motion/) for transitions and micro-interactions
- [Lucide](https://lucide.dev) for icons
- Static JSON as the data layer — no backend or database required

## Getting started

### Prerequisites

- [Node.js](https://nodejs.org) 18 or later
- npm (bundled with Node.js)

### Installation

```bash
git clone https://github.com/fadimuhammed/SIH-26-PS-EXPLORER.git
cd SIH-26-PS-EXPLORER
npm install
```

### Run locally

```bash
npm run dev
```

The app is served at `http://localhost:5173` with hot module reloading.

### Available scripts

| Command | Description |
| --- | --- |
| `npm run dev` | Start the Vite dev server |
| `npm run build` | Build a production bundle into `dist/` |
| `npm run preview` | Serve the production build locally |

## Data

The dataset lives entirely in [`public/data`](./public/data) as static JSON, split into two layers:

- `ps_list.json` is a light index (one entry per problem statement) used to power the home page, search, filters, and stats without downloading every analysis blob upfront.
- `ps/<PS_NUMBER>.json` holds the full record for a single problem statement, including the `overview`, `analysis`, `evaluator_lens`, `build_plan`, and `unlock_more` blocks rendered on its detail page. This is fetched only when that problem statement is opened.

> [!IMPORTANT]
> Problem statement data is mirrored from the official Smart India Hackathon portal ([sih.gov.in](https://sih.gov.in)) under CC BY 4.0. Deadlines and idea counts reflect the state of the data at the time it was captured and may not stay in sync with the live portal.

## Deployment

The project builds to static files and deploys cleanly to any static host. The live instance runs on [Vercel](https://vercel.com):

```bash
npm run build
```

This outputs a deployable `dist/` folder — point your static host's build command at `npm run build` and its output directory at `dist`.
